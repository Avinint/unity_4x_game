# Fief (Fantasy Fiefdoms)

Jeu 4X heroic fantasy réaliste sous Unity. Langue de travail : français, réponses brèves et précises.

## Méthode de travail
- Avant toute écriture (code, scène), montrer les changements prévus (diff ou extraits avant/après, fichiers concernés) et attendre la validation explicite de l'utilisateur. Pas d'écriture avant le feu vert.
- CLAUDE.md et ajouts à `.gitignore` : écrire directement, sans montrer le diff ; résumer en une ligne ce qui a changé.
- Mettre CLAUDE.md à jour dans la même étape que le changement qu'il décrit (pas après coup), pour qu'il parte dans le même commit.
- Travailler par petites étapes, une à la fois, et vérifier en jeu entre deux étapes.
- Ne jamais commiter : l'utilisateur commite lui-même.

## Environnement
- Unity 6000.6.4f1, Windows. Rendu : URP (`Assets/Settings/URP-HighFidelity.asset`).
- Cinemachine 3 (`Unity.Cinemachine`) : `CinemachineCamera`, `CinemachineOrbitalFollow`, `Lens`.
- Input : Input System seulement (`PlayerControls.inputactions` pour les actions, `Mouse.current` dans `MouseController` et pour le défilement par les bords). Active Input Handling à régler sur « Input System Package (New) » (Project Settings → Player).
- MCP Unity (Editor ouvert sur le projet, package `com.unity.pipeline`), selon l'ordinateur :
  - `M:\Unity_Projects\Fantasy Fiefdoms` : `unity mcp configure claude-code --project-path "M:\Unity_Projects\Fantasy Fiefdoms"`.
  - `C:\Users\avini\UnityProject\unity_4x_game` : entrée locale `claude mcp add --scope local --transport stdio unity-editor-mcp -- unity mcp --project-path "C:\Users\avini\UnityProject\unity_4x_game"` (ne pas utiliser `unity mcp configure` ici : il écrase l'entrée utilisateur du projet FPS).
- Sortir du mode Play avant une recompilation ou un appel MCP : l'Editor ne répond plus pendant ce temps.
- Après une recompilation, relancer le mode Play : une partie lancée pendant le rechargement des scripts garde un état cassé (caméra non inclinée, HUD jamais mis en page).
- Touches simulées par MCP (`simulate_key`) : n'atteignent pas les actions du jeu (la vue Game n'a pas le focus) ; tester le clavier à la main.
- Tests EditMode (`Assets/Tests/EditMode`) : `unity test` refuse de tourner si l'Editor est ouvert sur le projet ; les lancer depuis le Test Runner ou par MCP (`eval` avec `TestRunnerApi`). Hors mode Play et scène enregistrée seulement : sinon le Test Runner échoue (mode Play) ou ouvre une fenêtre « sauvegarder la scène ? » qui bloque l'Editor.
- Ne pas éditer `.unity`/`.prefab` à la main si l'Editor est ouvert : passer par les outils MCP.

## Architecture (Assets/Scripts)
- `Singleton<T>` : base des managers (`GameManager`, `CameraController`, `SelectionController`, `MouseController`, `MainThreadDispatcher`). Plus de `DontDestroyOnLoad` : ils appartiennent à la scène `Game` et disparaissent avec elle (sinon, après Game → menu → nouvelle partie, les anciens restaient, pointant sur une carte détruite, et les nouveaux levaient « Instance already exists ») ; `OnDestroy` (virtuel, `CameraController` l'appelle) oublie l'instance et note l'image (`_destroyedFrame`) : pendant le déchargement, les `OnDisable` / `OnDestroy` des autres objets lisent encore `Instance`, qui ne recrée pas de gestionnaire vide dans cette image.
- Menu et création de partie (en cours, étapes 1, 2 et 4 sur 4 faites, reste l'écran de création) : menu de la partie (étape 4) : `Scripts/UI/PauseMenu.cs` sur l'objet `HUD` (même `UIDocument`) ; bouton « Menu » en haut à gauche du HUD (`menuButton`) et Échap quand il n'y a rien à annuler (visée, puis sélection, puis menu, comme Civ ; `SelectionController.Deselect` ; Retour arrière, lié à la même action, ne l'ouvre pas) ; voile plein écran `pauseMenu` avec Reprendre, Menu principal (`GameSetup.Current = null`, chargement de `MainMenu`), Quitter ; Échap le referme (pas dans l'image où il s'est ouvert) ; ouvert, les commandes du jeu sont coupées (`PlayerInput.DeactivateInput` sur `CameraTarget`, `CameraController.IsLocked` : survol, clic du milieu, glissé, défilement par les bords) ; pas une pause du temps (une unité en marche finit son trajet). Styles des cadres et boutons partagés par les deux menus : `Assets/UI/Menu/MenuShared.uss` (`.menu-panel`, `.menu-button`), lu par `MainMenu.uxml` et `HUD.uxml`. Clés `Menu` : `menu.open` (Menu), `menu.resume` (Reprendre), `menu.main_menu` (Menu principal), `menu.quit` réutilisée. menu principal (étape 2) : scène `Assets/Scenes/MainMenu.unity` (index 0 du build, `Game` en 1 ; caméra à fond uni sombre, objet `MainMenu` = `UIDocument` avec `HUDPanelSettings` partagé, `Assets/UI/Menu/MainMenu.uxml` / `MainMenu.uss` aux couleurs du HUD, script `Scripts/UI/MainMenu.cs`) : titre « Fief » (nom propre, non traduit), boutons Nouvelle partie (en attendant l'écran de création : `GameSetup.Current = new GameSettings()` puis chargement de `Game`), Charger et Options grisés (`SetEnabled(false)`), Quitter (`Application.Quit`, ou sortie du mode Play dans l'Editor) ; textes dans la table `Menu` (`menu.new_game`, `menu.load`, `menu.options`, `menu.quit`), réécrits au changement de langue ; pas d'`EventSystem` (les boutons UI Toolkit n'en ont pas besoin ; à ajouter avec le module de l'Input System si les clics ne passent pas). Réglages (étape 1) : `GameSettings` (`Scripts/GameSettings.cs` : `Size` (`MapSize` Small / Medium / Large), `MapType`, `WrapWorld`, `PlayerCount` 2 à 5, `Seed` facultative) ; `GameSettings.Dimensions(taille, type)` (pur, testé, `GameSettingsTests`) : Petite 40×25, Moyenne 60×38, Grande 80×50, Pangée presque carrée à nombre de cases voisin (30×34, 46×50, 60×66) ; nos 40×25 sont petits à côté de Civ (de mémoire, Civ 6 « Duel » ~44×26, standard > 80×50), d'où la Petite = la carte actuelle ; `GameSetup.Current` (statique, survit au changement de scène ; null = scène `Game` lancée depuis l'Editor, l'Inspector garde la main) ; appliqué au début de `MapGenerator.GenerateMap` (`ApplyGameSetup` : `HexGrid.ApplySettings(largeur, hauteur, wrap)`, type, graine fixe ou au hasard) et dans `GameManager.InitPlayers` (seuls les `PlayerCount` premiers joueurs de la scène, les autres désactivés). Temps de `BuildCells` mesuré (sans l'instanciation des cases, non mesurée) : ~30 ms en Petite, ~50 à 90 ms en Moyenne et Grande. Étape suivante : écran de création (taille, type, joueurs, monde qui boucle, graine).
- `GameManager` : liste de `Player`, `InitPlayers` appelé sur `HexGrid.OnTileInstancesGenerated`, place les joueurs et unités de départ, événements `GameStart` / `TurnChange`. Tour par joueur : délégué à `TurnCycle<Player>` (classe pure testée, `TurnCycleTests` : ordre avec un premier joueur, `Advance()` renvoie true en début de manche, `Round`), créé en fin d'`InitPlayers` avec le joueur local en premier, puis `PlayerTurnStart(premier joueur)` levé pour ouvrir la partie ; `TurnOrder`, `CurrentPlayer`, `CurrentTurn` (= `Round`) en lecture. Entrée (`World/ChangeTurn` -> `ChangeTurn`, seulement si `CurrentPlayer == LocalPlayer` et si aucune de ses unités n'est en marche, `HasMovingUnit` : un tour n'est fini qu'une fois tous ses mouvements terminés ; l'IA devra de même attendre la fin de ses mouvements) termine le tour : `EndPlayerTurn` passe au suivant et lève `PlayerTurnStart(joueur)` ; après le dernier, nouvelle manche (`CurrentTurn++`, `TurnChange`). Les joueurs sans IA passent leur tour aussitôt (boucle jusqu'au retour du joueur local). `AddStartingUnits` passe chaque unité à `SetupStartingUnit` : ajout à `Player.units`, `Unit.Owner`, puis `Unit.UpdateVision(case)`. Brouillard par joueur : `GameManager.Fog` (`FogOfWar<Player>`) ; chaque joueur explore sa zone de départ (`Fog.Explore`) ; l'affichage suit le joueur local (`OnTileExplored` → `HexTile.Discover`) ; `RevealAllPlayers` n'affiche les zones des autres qu'en débogage.
- `FogOfWar<TPlayer>` : classe pure testée (`FogOfWarTests`). Par joueur, cases explorées (`HashSet`) et nombre d'unités qui voient chaque case (`Dictionary`, case vue si > 0). `Explore`, `AddWatcher`, `RemoveWatcher`, `IsExplored`, `IsVisible` ; événements `TileExplored` (une fois par case et par joueur) et `VisibilityChanged` (seulement aux transitions). Ne connaît pas la carte : l'appelant ne passe que des cases existantes (`HexGrid.CellsInRange`). Passage possible à des tableaux (index de case = ligne × Width + colonne) si une mesure le justifie.
- `UI/HUD` (UI Toolkit) : objet `HUD` de la scène (`UIDocument` + `HUD.cs`), fichiers dans `Assets/UI/HUD/` (`HUD.uxml`, `HUD.uss`, `HUDTheme.tss`, `HUDPanelSettings.asset`, 1920×1080 adapté à l'écran). Bande verticale transparente à droite (`rightBand`, 320 px), seuls deux cadres visibles, de même largeur (304 px), contenu centré, collés au bord de l'écran : en haut à droite (`turnPanel`, bordure sur les quatre côtés) une pastille à la couleur du joueur courant (`playerSwatch`, couleur posée par le code) puis « Tour N — Joueur 1 », mis à jour sur `TurnChange` et `PlayerTurnStart` ; en bas à droite (`unitPanel`, masqué sans sélection) l'unité sélectionnée et sa catégorie (« Guerrier (mêlée) », traduit), puis « Mouvement 1/2 », lus à chaque image dans `Update`. Fenêtre d'informations de la case survolée (comme Civ 6) : cadre `tileInfo` (position absolue, à côté du curseur à +16 px, passe de l'autre côté près des bords droit et bas), affiché seulement sur une case explorée (rien sur l'inconnu), fenêtre du jeu active (`Application.isFocused`), sans glissé de carte (`CameraController.IsDragging`), après `tileInfoDelay` (0,4 s) sans changer de case ; lignes par `TileInfo.Describe` (pur, testé, `TileInfoTests` : sol, ou seulement « Montagne » ; caractéristique ; « Accidenté » ; « Fleuve navigable » ; coût de déplacement ou « Infranchissable » pour l'eau et la montagne ; « Rivière » si une rivière d'arête borde la case ; « Eau douce » si `HexGrid.HasFreshWater`), traduites par `L10n.Get`, première ligne en gras ; réécrites au changement de langue. Plus tard : unités présentes, rendements, défense, propriétaire. Tous les éléments en `picking-mode="Ignore"`.
- Monde qui fait le tour (fait, 4 étapes) : option de carte `HexGrid.WrapWorld` (Inspector de `Grid`, décochée par défaut ; est-ouest seulement, les pôles restent des bords ; décochée pour un scénario à bords fixes), lue par `MapGenerator.WrapWorld` au lancement. Étape 1 (génération) : `Noise.GenerateNoiseMap(…, wrapX)` lit un bruit 3D (`Unity.Mathematics.noise.cnoise`, package `com.unity.mathematics` ajouté au manifeste et à `Fief.asmdef`) sur un cylindre (colonne → angle, rayon Width / 2π / scale : une case = même distance qu'en vertical), donc le bord ouest se raccorde au bord est (testé, `NoiseTests`) ; décalages propres tirés après les autres, les cartes à bords fixes sont inchangées ; `MapGenerator.Neighbours` ramène la colonne dans [0, Width) (côtes, lacs, hydrologie, largeur des fleuves traversent la couture). Étape 2 (logique de jeu) : `HexMetrics.WrapAxial(case, largeur)` ramène une case axiale dans les colonnes [0, Width) (cases à sommet pointu seulement) et `WrappedDistance` prend la plus courte vers b ± une largeur (testées) ; `HexGrid.Wraps` (= `WrapWorld` et sommet pointu), `Wrap(case)`, `Distance(a, b)` ; passent par `Wrap` : `TryGetTileAxial`, `HasRiver`, `SetNeighbours`, `CellsInRange` (sans doublon), `ObstacleAt` / `SurfaceAt` ; `CellsInSight` trace les lignes de vue sans `Wrap` (droites à travers la couture) puis ramène le résultat ; `DispatchPlayers` : bords nord / sud seulement (`HexTile.IsCloseToGridEdge(…, wrapX)`), masses de terre et distance entre départs bouclées. Fonctions pures avec paramètre optionnel (sans lui, rien ne change ; testées) : `PathFinder.FindPath(…, wrap, distance)` (voisin = wrap(case + direction), estimation = distance), `StartPositionPicker.LandmassSizes(…, wrap)` / `Pick(…, distance)`, `Hydrology.Navigable(…, wrapX)` (est / ouest ne sont plus des bords), `RiverNetwork.Rivers(…, wrap)` (sommets faits de cases ramenées ; direction de a vers b cherchée après bouclage). `SelectionController` passe `Grid.Wrap` / `Grid.Distance` au pathfinder. Étape 3 (affichage) : la caméra n'est plus bornée est-ouest (`CameraController.ClampTarget`, nord / sud seulement) ; chaque colonne est dessinée à la copie (± n × `HexGrid.WorldWidth`) la plus proche de la caméra : `HexMetrics.WrapShift(x, xCaméra, largeur)` (testé), `HexTile.ShiftX` / `SetShift` (déplace terrain et unités à l'arrêt ; `CentrePosition` inclut le décalage, donc unités, marqueurs, caméra suivent), recalculé dans `HexGrid.LateUpdate` quand la caméra a bougé d'au moins une case (remis à zéro dans `BuildRivers`), puis `ShiftVersion++` et `RiverView.Refresh` ; `HexGrid.NearestCopy(position, près)` ; `OnMouseMove` ramène la case touchée par `Wrap` ; `Unit.MoveRoutine` marche vers la copie la plus proche de l'unité puis se pose sur `CentrePosition` (un seul pas à la couture) ; `RiverView` garde les deux rives de chaque ligne et trace b à la copie la plus proche de a (arêtes de la couture comprises) ; aperçu du chemin : chaque pas à la copie la plus proche du précédent, recalculé si `ShiftVersion` change. Étape 4 (finitions) : survol fait : sous le brouillard, la souris touchait le maillage plat de `Grid`, qui ne couvre que la carte d'origine ; `MouseController.TryRaycastGrid` prend, faute de collider « Grid », le point du rayon sur le plan du sol, et `HexGrid.OnMouseMove` efface le survol hors de la carte (nord, sud). Recentrage fait : en défilant toujours dans le même sens, x de la caméra grandissait (~350 unités par tour du monde sur 40 colonnes, tremblements des `float` vers x ≈ 100 000) ; au début du tour du joueur local (`CameraController.OnPlayerTurnStart`), la cible est ramenée près du centre de la carte d'un nombre entier de `WorldWidth` (`WrapShift`), glissement `CenterOn` arrêté, puis `HexGrid.RefreshWrapShifts` replace les colonnes tout de suite (pas une image à vide) ; la vue reste identique. Sans risque car la fin de tour attend les mouvements (voir `GameManager`). Dézoom complet fait : en monde qui boucle, `CameraController.MaxDistance` = distance qui montre au plus 90 % de `WorldWidth` (`CameraMath.FitDistance`, marge `wrapMaxZoomFraction`, 0,9, réglable dans l'Inspector de la caméra, de 0,5 à 1), sans le plancher `distanceMax` (une vue plus large que le monde montrait le vide au bord : chaque colonne n'a qu'une copie).
- `Grid/MapGenerator` : quatre bruits (altitude, humidité graine+1, chaleur graine+2, crêtes graine+3) → `MapCell[,]` (`Relief`, `Biome`, `Terrain`), événement `OnTerrainMapGenerated(MapCell[,])`. Types de carte (faits : Fractal, Pangaea, Continents, Archipelago) : `MapGenerator.MapType` (Inspector, `Fractal` par défaut = bruit seul, la génération d'avant) ; `Grid/MapShape` (pur, testé, `MapShapeTests`) : `Mask(type, largeur, hauteur, rangées polaires, wrapX, aléa)` → masque 0 à 1 (null sans forme ; aléa = `System.Random(Seed + 4)`), mêlé à l'altitude juste après les bruits, avant le niveau de la mer (`altitude = Lerp(bruit, masque, Rules.ShapeWeight)`, 0,8 ; 0,5 laissait des ponts de terre entre continents ; réglé aussi dans la scène) : la mer restant un centile, la part de terres ne change pas, seule leur répartition ; `Bump` = bosse elliptique adoucie (smoothstep), écart en x pris à travers la couture en monde qui boucle. `Pangaea` (faite) : une bosse au centre, rayons 45 % de la largeur (océan à la couture) et 40 % de la hauteur jouable ; mesuré sur 5 graines (40×29) : la plus grande masse fait 86 à 98 % des terres (montagnes et fleuves compris), contre 49 à 95 % en `Fractal` (sur une petite carte le bruit seul donne déjà souvent une grande masse ; la Pangée ajoute surtout l'océan tout autour). Ses rayons suivent les proportions de la carte (une colonne fait 1,73 de large, une rangée 1,5 de haut : 40×25 est 1,85 fois plus large que haut, la Pangée y est allongée) ; format choisi pour la Pangée : 30×34 (à peu près carré) ; à l'écran de création de partie, taille par défaut selon le type de carte (Pangée carrée, Continents large). `Continents` (faits) : `ContinentCount` = 2, 3 si largeur ≥ 60 ; `ContinentCentres` : répartis en x à intervalles réguliers (bords fixes : le premier à un demi-intervalle du bord, centrés sur (largeur − 1) / 2 ; monde qui boucle : départ au hasard), décalés au hasard de ± 5 % de l'intervalle en x et ± 10 % de la hauteur jouable en y ; bosses de rayon 35 % de l'intervalle en x (40 % : les bosses couvraient plus que la part des terres, la mer tombait à leur bord et le bruit reliait les continents) et 40 % de la hauteur jouable ; chenal d'océan garanti (`OceanChannels`, testé : 3 colonnes à mi-chemin entre continents voisins, couture comprise en monde qui boucle ; altitude passée sous la mer après son calcul, comme la banquise ; îles en pleine mer gardées) : sinon le bruit gardait un pont de terre sur 2 graines sur 10 ; mesuré sur 5 graines × 2 (40×29) : deux continents séparés à chaque fois (ex. 214 / 206, 196 / 188 cases), terres 38 à 42 % au lieu de 42 % (les ponts noyés). `Archipelago` (fait) : plus d'eau (`Rules.ArchipelagoWaterFraction` 0,65 au lieu de `WaterFraction`, passé aussi au masque comme part des terres) ; îles moyennes plutôt qu'un bruit plus fin (qui aurait donné des îlots d'une case, trop petits pour la règle `startMinLandmass`) : `IslandCount` = une île pour 80 cases jouables, au moins 4 (12 sur 40×25) ; `IslandBumps` (testé) : rayon moyen tel que les îles couvrent la part des terres, × 0,7 à 1,3 au hasard, × 1,15 en y (`RowsPerColumn` : une colonne 1,73, une rangée 1,5, îles rondes à l'écran) ; placées au hasard dans la bande jouable (demi-île de marge au nord et au sud, et à l'est / ouest en bords fixes), à au moins 2 rayons moyens des autres si un des 50 essais le permet, sinon au plus éloigné (`Gap`, écart à travers la couture) ; pas de chenal garanti (deux îles qui se touchent en font une plus grande). Mesuré sur 5 graines × 2 (40×25) : 10 à 21 îles, terres 35 %, 5 à 10 masses à pied assez grandes pour un départ (≥ 15 cases à 5 joueurs). Niveau de la mer = percentile `Rules.WaterFraction` ; puis chaînes de montagnes : `MapRules.AddRidges` (testé) mêle l'altitude des terres à des crêtes (1 − |2n − 1|) selon `RidgeWeight` (0,7 : chaînes nettes ; 0,5 donnait des groupes courts), l'eau et les côtes restent intactes ; l'altitude ainsi obtenue sert à tout le reste (relief, rivières, température, `ReliefMap`) ; collines / montagnes / basses terres = percentiles des seules terres ; latitude = y / (Height−1) (0 sud, 1 nord) ; côtes par `MapRules.CoastMask` avec les vrais voisins hexagonaux (`HexMetrics`). Terrain affiché (`TerrainFor`) : `MountainTerrain` pour une montagne, `RiverTerrain` pour un fleuve navigable, sinon la caractéristique (`FeatureTerrains` : Forest → `Forest`, Taiga → `Taiga`, Rainforest → `Jungle`, Marsh → `Marsh`, Snow → `Snow`), sinon le sol (`BiomeTerrains` : Ocean, Coast, Lake, Tundra → `Toundra`, Grassland, Plains → `Plain`, Desert, Tropical → `Tropical`, asset Id 14, `tropical.prefab` / `Tropical.mat` copiés de la plaine, #9ACD32) ; listes réglées dans la scène (reconstruites par MCP au passage aux trois couches). Banquise : `HexGrid.PolarIceRows` (2 par défaut, 0 à 4 ; 0 pour une carte régionale ou un scénario) rangées ajoutées à chaque pôle, lues par `MapGenerator.PolarIceRows` ; `MapRules.IsPolar` / `IsIceEdge` (testés) ; niveau de la mer calculé hors rangées polaires (la banquise ne compte pas dans `WaterFraction`), puis leur altitude passée sous la mer avant côtes, lacs et hydrologie ; ces rangées = eau + `Feature.Ice` (biome Ocean ou Coast) ; la rangée qui les touche gèle sur la part `IceEdgeFraction` (0,5) de ses cases d'eau les plus froides (centile propre à cette rangée, température au niveau de la mer : le seuil de la neige, tiré des hautes terres refroidies par l'altitude, ne gelait jamais la mer), d'où une limite irrégulière. Asset `Ice.asset` (Id 15) + `ice.prefab` / `Ice.mat` (copies de la neige, bleu glacier #BDDDFD, réglé à l'œil), entrée `Ice → Ice` dans `FeatureTerrains`. Fenêtre de la case : « Océan / Banquise / Infranchissable ». Plus d'inversion des axes : la case (x, y) générée est la case offset (x, y) du jeu. Carte de couleurs : `ColorMap` (une couleur par case, `TerrainType.Colour`, `GenerateColorsFromCells`) et `OnColorMapGenerated`, calculés à chaque génération mais sans abonné (reste de l'ancien aperçu) ; gardés pour une future mini-carte (texture d'une case par pixel) : garder `Colour` de chaque `TerrainType` aligné sur la couleur de son matériau (fait pour la banquise ; les autres non vérifiés).
- Terrain en trois couches (comme Civ 7) : `Relief` (Water, Flat, Hill = « Accidenté » à l'affichage, Mountain, NavigableRiver : le fleuve navigable est un relief, eau pour le déplacement, la case garde son sol et sa végétation, pour les rives et les rendements), `Biome` = le sol (Ocean, Coast, Lake, Tundra, Grassland, Plains, Desert, Tropical ; « Plaine tropicale » en français), `Feature` = caractéristique (None, Forest, Taiga, Rainforest « Forêt tropicale », Marsh, Snow, Ice « Banquise » ; la neige est une caractéristique de la toundra, la banquise de l'eau). Nouvelles valeurs toujours en fin d'enum (listes de la scène enregistrées par numéro). `MapRules.IsWater` (eau ou fleuve), `IsPassable` (plat ou accidenté), `MovementCost(relief, caractéristique)` = 1, +1 pour une caractéristique, +1 en accidenté (testé ; remplace l'ancien `TerrainType.MovementCost`). Plus tard : autres caractéristiques par biome (savane boisée, steppe, oasis, tourbière, mangrove), plaines inondables, glace, volcan.
- `Grid/MapRules` (règles pures testées, `MapRulesTests`) : `MapRulesSettings` (eau 55 %, collines 25 % et montagnes 8 % des terres (6 % : trop peu de cases pour former des chaînes), `RidgeWeight`, poids de la latitude, refroidissement en altitude 0,2, climat en proportions des terres : `FrozenFraction` 5 % (neige), `TundraFraction` 8 % (toundra quelle que soit l'humidité), `ColdFraction` 12 % (taïga, toundra si sec), `HotFraction` 20 %, donc 55 % de tempéré, `DryFraction` 25 %, `WetFraction` 25 %, `MarshFraction` 8 % ; seuils absolus cachés, calculés à chaque génération par `WithClimateThresholds`, testé, qui ne modifie pas les réglages). `Percentile` (seuils d'altitude en proportions, indépendants de la graine), `ReliefAt`, `Temperature` (latitude : pôles froids, équateur chaud ; refroidit en altitude ; non bornée : borner à 0 créait aux pôles plus de 5 % d'ex aequo, et plus aucune neige), `LandBiome` → (sol, caractéristique) (tableau température × humidité type Whittaker : glacial → toundra + neige ; très froid → toundra ; froid → toundra, + taïga si pas sec ; tempéré → plaines si sec, prairie, + forêt si humide ; chaud → désert si sec, plaine tropicale, + forêt tropicale si humide ; marais (prairie + marais) sur terres plates basses très humides non froides), `BlocksSight` / `ObstacleHeight` sur la caractéristique (forêt, taïga, forêt tropicale), `WaterBiome` (côte si voisine d'une terre), `CoastMask`. Limite : une petite étendue collée au bord de la carte devient aussi un lac. Assets `Lake.asset` (Id 13) + `lake.prefab` / `Lake.mat` (copies du fleuve, bleu franc 0,30 / 0,55 / 0,90), entrée `Lake → Lake` dans `BiomeTerrains` de la scène. ## État du jeu
- Fait : génération de carte, brouillard (`IsDiscovered`), placement des joueurs, caméras, survol et sélection d'unité (marqueurs), déplacement par chemin animé, points de mouvement, tour par joueur (ordre fixe, joueur local d'abord, joueurs sans IA passés automatiquement), HUD (numéro de tour, joueur courant, unité sélectionnée et points restants), exploration (vision des unités), aperçu du chemin au survol.
- Ordre prévu : exploration (faite), traduction (faite, sauf le choix de langue dans un menu d'options), fleuves et lacs (faits), qualité des départs (faite), puis fondation des villes (gameplay villes et combats dans une autre session ; celle-ci reste pour la génération de carte et les bases du jeu, menus compris).
- Fleuves prévus (modèle Civ 7) : un calcul de débit à la génération (fonction pure testée : l'eau descend selon l'altitude, chaque case accumule le débit de son bassin versant ; seuils en proportions dans `MapRulesSettings`). Débit moyen = rivière sur les arêtes (entre deux cases voisines, ensemble d'arêtes dans `MapCell` / `HexTile`, `HasRiver(a, b)`) ; débit fort, vers l'embouchure = fleuve navigable sur les cases : `Relief.Water` + nouveau biome `River` (eau douce ; hérite d'`IsLand` faux, hauteur 0, pas de socle ; pas de relief `River`, qui obligerait à revoir les tests `Relief == Water`). Fréquence : chaque case de terre apporte son humidité au débit (beaucoup de rivières en zone humide, peu en désert, mais un grand fleuve peut traverser un désert par cumul, comme le Nil) ; seuils en percentiles des cases de terre (`RiverFraction` ~15 % de cases bordées par une rivière, `NavigableFraction` ~2–3 %), seuils absolus recalculés à chaque génération (fonction testée, comme `WithClimateThresholds`) ; garde-fous réglables : longueur minimale (~3 arêtes), cuvettes sans pente vers la mer (vers la voisine la plus basse, ou lac d'eau douce). Réglage à l'œil (`RandomSeed`, `RevealWholeMap`, Inspector de `MapGenerator`) : assez de rivières pour que l'eau douce compte dans le choix d'une ville, pas un fleuve à traverser à chaque tour. Gorges : naturelles (le fleuve suit les vallées, eau à hauteur 0 entre des collines). ## Pistes de conception (non décidées)
- Références : Civilization (5, 6, 7) et At the Gates (Jon Shafer). Direction encore ouverte entre les deux : At the Gates = une région (pas le monde entier), une seule époque (pas de changement d'âge), progression par les personnages : ils acquièrent des compétences qui débloquent unités, bâtiments et capacités (au lieu d'un arbre technologique) ; colle au thème des fiefs (seigneurs, vassaux). Conséquences possibles : carte régionale à bords fixes par défaut (`WrapWorld` reste une option), latitude réglable plutôt que pôles obligatoires. À trancher avec le gameplay (session villes et combats).
- Marqueurs observés dans Civ 6 (pour s'en inspirer, sans recopier) : unité sélectionnée = cercle plat blanc (deux cercles concentriques, une rose des vents / boussole dessinée au sol entre eux, petits rayons autour), et des rayons de lumière qui descendent du ciel sur elle ; survol d'une case = fenêtre d'informations près du curseur (terrain, coût en points de mouvement, attrait, continent, rendements) ; pendant le clic droit seulement (bouton maintenu ; l'ordre part au relâchement), le chemin vers la case visée est un trait en pointillés 3D (tirets clairs), et un cercle plat (avec de petits repères) marque la destination : doré si atteignable, rouge si infranchissable (sans trait), marron chocolat si la destination est hors du champ de vision, bleu marine (≈ 0,10 / 0,15 / 0,45) une fois relâché si l'unité n'a plus de points (trait et cercle restent affichés, mais l'unité ne suit pas le chemin d'elle-même au tour suivant) ; le trait est d'une seule couleur, avec une pastille numérotée (1, 2, 3…) sur la dernière case atteinte à chaque tour, la dernière sur la destination ; à la sélection, la zone atteignable ce tour-ci est entourée d'un contour cyan ; la fenêtre de survol détaille aussi bois, modificateur de défense, rendements. Étendards d'unité : au-dessus de chaque unité, une icône de son type sur un fond à la couleur de son joueur (à la place d'un blason sur l'unité) ; deux unités sur une case = deux icônes côte à côte, un clic sur l'une sélectionne cette unité (en plus du reclic sur l'unité, qui passe à la suivante) ; règle aussi la superposition des modèles sans les décaler ; à faire avec le combat (session gameplay : l'étendard portera aussi la santé de l'unité). Unité suivante (à créer, comme Civ 6) : dès que l'unité sélectionnée n'a plus de points (à la fin de son déplacement), la sélection passe à la prochaine unité du joueur qui a encore des points, et la vue glisse jusqu'à elle (`CenterOn`) ; aussi par une touche ou un bouton ; quand plus aucune unité n'a de points, le bouton de fin de tour le signale ; à décider : ordre de passage (la plus proche ? ordre de création ?), unités qu'on ne veut pas bouger (passer, fortifier) ; à faire avec la structure du tour (session gameplay). Structure du tour, non décidée : aujourd'hui tours successifs (joueur local d'abord) ; à trancher : successifs ou simultanés, phases (mouvements, combats, production) ou non, ordres sur plusieurs tours, états d'unité (fortifiée, sentinelle, passer) qui décident quelles unités attendent un ordre ; l'IA joue ses unités dans son propre ordre, sans lien avec l'« unité suivante ». Commandes : clic gauche glissé = saisir la carte et la faire glisser (le point saisi reste sous le curseur), clic gauche bref = sélection ; d'où le déplacement au clic droit maintenu, relâché sur la destination.

- Variantes du relief accidenté par biome (avec les modèles réalistes) : erg (dunes) dans le désert, et d'autres possibles (moraines en toundra, karst, badlands, champs de lave).

## Règles de jeu décidées
- Une unité ne peut ni s'arrêter sur la case d'une unité d'un autre joueur, ni la traverser, sauf si un événement change la règle (alliance). Code : `IsWalkable` exclut `HexTile.HasUnitOfOtherPlayer(owner)` sur les cases vues en ce moment par le propriétaire (`IsWalkableFor(owner, explored, seenNow)`, testé) ; l'aperçu montre ces cases en rouge. Hors vue, l'unité ennemie est ignorée (pas de fuite d'information) ; un ennemi découvert en route arrête l'unité (`Unit.CanEnter`, voir `SelectionController`).
- Ordre vers la case d'une unité d'un autre joueur = attaque (à concevoir avec le combat : unité civile / militaire, dégâts, riposte). En attendant, refusé.
- Empilement (comme Civ 5 / 6) : au plus une unité civile et une militaire par joueur et par case (à ajuster plus tard). On peut traverser une case pleine de ses unités, pas s'y arrêter. Code : `HexTile.CanStop(unit)` (même propriétaire et même famille `IsMilitary`, l'unité elle-même ignorée, testé) ; case visée pleine = interdite (aperçu rouge, `PathTo` renvoie null) ; si les points s'épuisent sur une case pleine, l'unité s'arrête sur la dernière case libre (`PathFinder.LastStop`, testé, partagé par `Command` et l'aperçu via `StopCount`). Plus tard : échange de places entre deux unités amies voisines (Civ 6 ; pendant la visée, le cercle de destination s'affiche alors sur les cases des deux unités), formations.
- À décider : zones de contrôle (plus tard).

- `Player.StartingTile` / `StartingArea` : données calculées au lancement, `[NonSerialized]` (ni enregistrées ni visibles dans l'Inspector).

## Révélation des zones de départ
- `GameManager.LocalPlayer` (champ `localPlayer`, par défaut le premier de `Players`) et `RevealAllPlayers` (coché par défaut, débogage). Décoché, seule la zone du joueur local est révélée et la caméra démarre sur sa case.
- `GameManager.RevealWholeMap` (débogage, décoché par défaut) : en fin d'`InitPlayers`, toutes les cases découvertes et visibles (`HexGrid.AllTiles`), et `OnVisibilityChanged` ignoré pour que tout reste visible. Affichage seulement (la connaissance `FogOfWar` n'est pas touchée) ; le déplacement suit la connaissance du propriétaire, pas cet affichage.
- Graine de carte : `MapGenerator.Seed` (les trois bruits en dépendent). `RandomSeed` (coché par défaut) : en jeu, nouvelle graine au hasard à chaque partie, affichée dans la console (« MapGenerator : graine N ») ; décocher et recopier la graine dans `Seed` pour rejouer une carte. Hors du mode Play, l'aperçu de l'Inspector garde `Seed`.
- Taille de carte : se règle uniquement sur `HexGrid` (Width / `MapHeight`, 10 à 100 ; `MapHeight` = terres jouables, l'ancien champ `Height` repris par `FormerlySerializedAs`, et `Height` = `MapHeight` + 2 × `PolarIceRows`, lu par tout le reste du code) ; `MapGenerator` la lit au lancement de la génération (plus de Width / Height / UseHexGrid propres). Réglée à 40×25 dans la scène (grille 40×29 avec la banquise) (20×20 était petit pour 5 joueurs : ~14 cases utiles chacun).
- Les unités posées sur des cases cachées sont masquées (voir `HexTile`).
- Exploration : les unités révèlent les cases autour d'elles en se déplaçant, dans la connaissance de leur propriétaire ; seul le joueur local est affiché ; on peut envoyer une unité dans l'inconnu (voir `SelectionController`).
- Ligne de vue (faite) : `LineOfSight.Visible` (classe pure testée, `LineOfSightTests`) trace la ligne hexagonale (`HexMetrics.AxialLine`, testée ; décalage ± pour les lignes le long d'une arête : vue si l'un des deux côtés est dégagé) vers chaque case du rayon. Hauteurs (`MapRules`, testé) : œil = `SightHeight` du relief (plat / eau 0, colline 2, montagne 4) ; obstacle = `ObstacleHeight` = relief + 1 pour forêt, taïga, jungle (`BlocksSight`). Une case intermédiaire cache la case visée si elle est plus haute que l'œil et au moins aussi haute que le sommet de la case visée : on voit ce qui dépasse (colline derrière une forêt, montagne derrière une forêt en colline), pas ce qui est de même hauteur (montagne derrière une montagne : cachée). Depuis une colline, on voit par-dessus forêts et collines, pas par-dessus une forêt en colline ni une montagne. Proche de Civ 5 / 6 (points sûrs : l'obstacle est vu, colline au-dessus des forêts, montagne bloque). Les cases voisines sont toujours vues. Branché dans `HexGrid.CellsInSight` (utilisé par `Unit.UpdateVision`) ; la zone de départ explorée reste un disque entier. Option possible : +1 de rayon en colline.
- Rendu du brouillard provisoire : les cases actuelles sont des couleurs unies minimalistes, à remplacer par des modèles plus réalistes. À revoir alors : désaturation par shader (Shader Graph, paramètre « brume » par case), voile ou nuages au-dessus des cases, ou passe de rendu plein écran ; la brume par `_BaseColor` continuera de teinter des matériaux texturés mais risque d'être trop simple.
