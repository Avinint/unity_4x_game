# Fief (Fantasy Fiefdoms)

Jeu 4X heroic fantasy réaliste sous Unity. Langue de travail : français, réponses brèves et précises.

## Méthode de travail
- Avant toute écriture (code, scène), montrer les changements prévus (diff ou extraits avant/après, fichiers concernés) et attendre la validation explicite de l'utilisateur. Pas d'écriture avant le feu vert.
- CLAUDE.md et ajouts à `.gitignore` : écrire directement, sans montrer le diff ; résumer en une ligne ce qui a changé.
- Mettre CLAUDE.md à jour dans la même étape que le changement qu'il décrit (pas après coup), pour qu'il parte dans le même commit.
- Travailler par petites étapes, une à la fois, et vérifier en jeu entre deux étapes.
- Ne jamais commiter : l'utilisateur commite lui-même.

## Environnement
- Unity 6000.6.4f1, Windows. Rendu : URP (`Assets/Settings/URP-HighFidelity.asset`).
- Cinemachine 3 (`Unity.Cinemachine`) : `CinemachineCamera`, `CinemachineOrbitalFollow`, `Lens`.
- Input : Input System seulement (`PlayerControls.inputactions` pour les actions, `Mouse.current` dans `MouseController` et pour le défilement par les bords). Active Input Handling à régler sur « Input System Package (New) » (Project Settings → Player).
- MCP Unity (Editor ouvert sur le projet, package `com.unity.pipeline`), selon l'ordinateur :
  - `M:\Unity_Projects\Fantasy Fiefdoms` : `unity mcp configure claude-code --project-path "M:\Unity_Projects\Fantasy Fiefdoms"`.
  - `C:\Users\avini\UnityProject\unity_4x_game` : entrée locale `claude mcp add --scope local --transport stdio unity-editor-mcp -- unity mcp --project-path "C:\Users\avini\UnityProject\unity_4x_game"` (ne pas utiliser `unity mcp configure` ici : il écrase l'entrée utilisateur du projet FPS).
- Sortir du mode Play avant une recompilation ou un appel MCP : l'Editor ne répond plus pendant ce temps.
- Après une recompilation, relancer le mode Play : une partie lancée pendant le rechargement des scripts garde un état cassé (caméra non inclinée, HUD jamais mis en page).
- Touches simulées par MCP (`simulate_key`) : n'atteignent pas les actions du jeu (la vue Game n'a pas le focus) ; tester le clavier à la main.
- Tests EditMode (`Assets/Tests/EditMode`) : `unity test` refuse de tourner si l'Editor est ouvert sur le projet ; les lancer depuis le Test Runner ou par MCP (`eval` avec `TestRunnerApi`). Hors mode Play et scène enregistrée seulement : sinon le Test Runner échoue (mode Play) ou ouvre une fenêtre « sauvegarder la scène ? » qui bloque l'Editor.
- Ne pas éditer `.unity`/`.prefab` à la main si l'Editor est ouvert : passer par les outils MCP.

## Architecture (Assets/Scripts)
- `Singleton<T>` : base des managers (DontDestroyOnLoad seulement si l'objet est à la racine).
- `GameManager` : liste de `Player`, `InitPlayers` appelé sur `HexGrid.OnTileInstancesGenerated`, place les joueurs et unités de départ, événements `GameStart` / `TurnChange`. Tour par joueur : délégué à `TurnCycle<Player>` (classe pure testée, `TurnCycleTests` : ordre avec un premier joueur, `Advance()` renvoie true en début de manche, `Round`), créé en fin d'`InitPlayers` avec le joueur local en premier, puis `PlayerTurnStart(premier joueur)` levé pour ouvrir la partie ; `TurnOrder`, `CurrentPlayer`, `CurrentTurn` (= `Round`) en lecture. Entrée (`World/ChangeTurn` -> `ChangeTurn`, seulement si `CurrentPlayer == LocalPlayer` et si aucune de ses unités n'est en marche, `HasMovingUnit` : un tour n'est fini qu'une fois tous ses mouvements terminés ; l'IA devra de même attendre la fin de ses mouvements) termine le tour : `EndPlayerTurn` passe au suivant et lève `PlayerTurnStart(joueur)` ; après le dernier, nouvelle manche (`CurrentTurn++`, `TurnChange`). Les joueurs sans IA passent leur tour aussitôt (boucle jusqu'au retour du joueur local). `AddStartingUnits` passe chaque unité à `SetupStartingUnit` : ajout à `Player.units`, `Unit.Owner`, puis `Unit.UpdateVision(case)`. Brouillard par joueur : `GameManager.Fog` (`FogOfWar<Player>`) ; chaque joueur explore sa zone de départ (`Fog.Explore`) ; l'affichage suit le joueur local (`OnTileExplored` → `HexTile.Discover`) ; `RevealAllPlayers` n'affiche les zones des autres qu'en débogage.
- `FogOfWar<TPlayer>` : classe pure testée (`FogOfWarTests`). Par joueur, cases explorées (`HashSet`) et nombre d'unités qui voient chaque case (`Dictionary`, case vue si > 0). `Explore`, `AddWatcher`, `RemoveWatcher`, `IsExplored`, `IsVisible` ; événements `TileExplored` (une fois par case et par joueur) et `VisibilityChanged` (seulement aux transitions). Ne connaît pas la carte : l'appelant ne passe que des cases existantes (`HexGrid.CellsInRange`). Passage possible à des tableaux (index de case = ligne × Width + colonne) si une mesure le justifie.
- `UI/HUD` (UI Toolkit) : objet `HUD` de la scène (`UIDocument` + `HUD.cs`), fichiers dans `Assets/UI/HUD/` (`HUD.uxml`, `HUD.uss`, `HUDTheme.tss`, `HUDPanelSettings.asset`, 1920×1080 adapté à l'écran). Bande verticale transparente à droite (`rightBand`, 320 px), seuls deux cadres visibles, de même largeur (304 px), contenu centré, collés au bord de l'écran : en haut à droite (`turnPanel`, bordure sur les quatre côtés) une pastille à la couleur du joueur courant (`playerSwatch`, couleur posée par le code) puis « Tour N — Joueur 1 », mis à jour sur `TurnChange` et `PlayerTurnStart` ; en bas à droite (`unitPanel`, masqué sans sélection) l'unité sélectionnée et sa catégorie (« Guerrier (mêlée) », traduit), puis « Mouvement 1/2 », lus à chaque image dans `Update`. Tous les éléments en `picking-mode="Ignore"`.
- Monde qui fait le tour (fait, 4 étapes) : option de carte `HexGrid.WrapWorld` (Inspector de `Grid`, décochée par défaut ; est-ouest seulement, les pôles restent des bords ; décochée pour un scénario à bords fixes), lue par `MapGenerator.WrapWorld` au lancement. Étape 1 (génération) : `Noise.GenerateNoiseMap(…, wrapX)` lit un bruit 3D (`Unity.Mathematics.noise.cnoise`, package `com.unity.mathematics` ajouté au manifeste et à `Fief.asmdef`) sur un cylindre (colonne → angle, rayon Width / 2π / scale : une case = même distance qu'en vertical), donc le bord ouest se raccorde au bord est (testé, `NoiseTests`) ; décalages propres tirés après les autres, les cartes à bords fixes sont inchangées ; `MapGenerator.Neighbours` ramène la colonne dans [0, Width) (côtes, lacs, hydrologie, largeur des fleuves traversent la couture). Étape 2 (logique de jeu) : `HexMetrics.WrapAxial(case, largeur)` ramène une case axiale dans les colonnes [0, Width) (cases à sommet pointu seulement) et `WrappedDistance` prend la plus courte vers b ± une largeur (testées) ; `HexGrid.Wraps` (= `WrapWorld` et sommet pointu), `Wrap(case)`, `Distance(a, b)` ; passent par `Wrap` : `TryGetTileAxial`, `HasRiver`, `SetNeighbours`, `CellsInRange` (sans doublon), `ObstacleAt` / `SurfaceAt` ; `CellsInSight` trace les lignes de vue sans `Wrap` (droites à travers la couture) puis ramène le résultat ; `DispatchPlayers` : bords nord / sud seulement (`HexTile.IsCloseToGridEdge(…, wrapX)`), masses de terre et distance entre départs bouclées. Fonctions pures avec paramètre optionnel (sans lui, rien ne change ; testées) : `PathFinder.FindPath(…, wrap, distance)` (voisin = wrap(case + direction), estimation = distance), `StartPositionPicker.LandmassSizes(…, wrap)` / `Pick(…, distance)`, `Hydrology.Navigable(…, wrapX)` (est / ouest ne sont plus des bords), `RiverNetwork.Rivers(…, wrap)` (sommets faits de cases ramenées ; direction de a vers b cherchée après bouclage). `SelectionController` passe `Grid.Wrap` / `Grid.Distance` au pathfinder. Étape 3 (affichage) : la caméra n'est plus bornée est-ouest (`CameraController.ClampTarget`, nord / sud seulement) ; chaque colonne est dessinée à la copie (± n × `HexGrid.WorldWidth`) la plus proche de la caméra : `HexMetrics.WrapShift(x, xCaméra, largeur)` (testé), `HexTile.ShiftX` / `SetShift` (déplace terrain et unités à l'arrêt ; `CentrePosition` inclut le décalage, donc unités, marqueurs, caméra suivent), recalculé dans `HexGrid.LateUpdate` quand la caméra a bougé d'au moins une case (remis à zéro dans `BuildRivers`), puis `ShiftVersion++` et `RiverView.Refresh` ; `HexGrid.NearestCopy(position, près)` ; `OnMouseMove` ramène la case touchée par `Wrap` ; `Unit.MoveRoutine` marche vers la copie la plus proche de l'unité puis se pose sur `CentrePosition` (un seul pas à la couture) ; `RiverView` garde les deux rives de chaque ligne et trace b à la copie la plus proche de a (arêtes de la couture comprises) ; aperçu du chemin : chaque pas à la copie la plus proche du précédent, recalculé si `ShiftVersion` change. Étape 4 (finitions) : survol fait : sous le brouillard, la souris touchait le maillage plat de `Grid`, qui ne couvre que la carte d'origine ; `MouseController.TryRaycastGrid` prend, faute de collider « Grid », le point du rayon sur le plan du sol, et `HexGrid.OnMouseMove` efface le survol hors de la carte (nord, sud). Recentrage fait : en défilant toujours dans le même sens, x de la caméra grandissait (~350 unités par tour du monde sur 40 colonnes, tremblements des `float` vers x ≈ 100 000) ; au début du tour du joueur local (`CameraController.OnPlayerTurnStart`), la cible est ramenée près du centre de la carte d'un nombre entier de `WorldWidth` (`WrapShift`), glissement `CenterOn` arrêté, puis `HexGrid.RefreshWrapShifts` replace les colonnes tout de suite (pas une image à vide) ; la vue reste identique. Sans risque car la fin de tour attend les mouvements (voir `GameManager`). Dézoom complet fait : en monde qui boucle, `CameraController.MaxDistance` = distance qui montre au plus 90 % de `WorldWidth` (`CameraMath.FitDistance`, marge 0,9), sans le plancher `distanceMax` (une vue plus large que le monde montrait le vide au bord : chaque colonne n'a qu'une copie).
- `Grid/MapGenerator` : quatre bruits (altitude, humidité graine+1, chaleur graine+2, crêtes graine+3) → `MapCell[,]` (`Relief`, `Biome`, `Terrain`), événement `OnTerrainMapGenerated(MapCell[,])`. Niveau de la mer = percentile `Rules.WaterFraction` ; puis chaînes de montagnes : `MapRules.AddRidges` (testé) mêle l'altitude des terres à des crêtes (1 − |2n − 1|) selon `RidgeWeight` (0,7 : chaînes nettes ; 0,5 donnait des groupes courts), l'eau et les côtes restent intactes ; l'altitude ainsi obtenue sert à tout le reste (relief, rivières, température, `ReliefMap`) ; collines / montagnes / basses terres = percentiles des seules terres ; latitude = y / (Height−1) (0 sud, 1 nord) ; côtes par `MapRules.CoastMask` avec les vrais voisins hexagonaux (`HexMetrics`). Terrain affiché : `MountainTerrain` pour une montagne, sinon `BiomeTerrains` (liste Biome → TerrainType, réglée dans la scène). Plus d'inversion des axes : la case (x, y) générée est la case offset (x, y) du jeu.
- `Grid/MapRules` (règles pures testées, `MapRulesTests`) : `Relief` (Water, Flat, Hill, Mountain), `Biome` (Ocean, Coast, Grassland, Plain, Desert, Forest, Taiga, Jungle, Tundra, Snow, Marsh, River, Lake), `MapRulesSettings` (eau 55 %, collines 25 % et montagnes 8 % des terres (6 % : trop peu de cases pour former des chaînes), `RidgeWeight`, poids de la latitude, refroidissement en altitude 0,2, climat en proportions des terres : `FrozenFraction` 5 % (neige), `TundraFraction` 8 % (toundra quelle que soit l'humidité), `ColdFraction` 12 % (taïga, toundra si sec), `HotFraction` 20 %, donc 55 % de tempéré, `DryFraction` 25 %, `WetFraction` 25 %, `MarshFraction` 8 % ; seuils absolus cachés, calculés à chaque génération par `WithClimateThresholds`, testé, qui ne modifie pas les réglages). `Percentile` (seuils d'altitude en proportions, indépendants de la graine), `ReliefAt`, `Temperature` (latitude : pôles froids, équateur chaud ; refroidit en altitude), `LandBiome` (tableau température × humidité type Whittaker : glacial → neige ; très froid → toundra ; froid → toundra si sec, sinon taïga ; tempéré → plaine / prairie / forêt ; chaud → désert / plaine / jungle ; marais sur terres plates basses très humides non froides), `WaterBiome` (côte si voisine d'une terre), `CoastMask`. Lacs : `LakeMask` (testé) marque les étendues d'eau (cases d'eau voisines entre elles) de `LakeMaxSize` (6) cases au plus ; dans `BuildCells` elles prennent le biome `Lake` (eau douce, relief `Water` : hauteur 0, infranchissable, rivières et fleuves s'y jettent ; évite les « mers » d'une case où débouchait un fleuve). Limite : une petite étendue collée au bord de la carte devient aussi un lac. Assets `Lake.asset` (Id 13) + `lake.prefab` / `Lake.mat` (copies du fleuve, bleu franc 0,30 / 0,55 / 0,90), entrée `Lake → Lake` dans `BiomeTerrains` de la scène. Plus tard : eau douce pour les villes.
- Relief visible : `HexGrid` section « Relief » (`hillHeight` 1,5, `mountainHeight` 4, `ElevationOf` → `MapRules.Elevation`, testé). `HexTile.Elevation` calculée dans `CreateTerrain` ; `CentrePosition` inclut la hauteur (unités, marqueurs, aperçu, caméra suivent ; unités de départ posées sur `tile.CentrePosition`). Sous le brouillard le modèle inconnu reste à plat (ne trahit pas le relief) ; à la révélation, terrain en hauteur + socle (`AddPlinth` : prisme hexagonal sans couvercle `HexGrid.PlinthMesh` / `HexMetrics.BuildPlinthMesh`, testé, même matériau que le terrain, brume comprise). `AddGizmo` ne déplace plus le terrain.
- `HexTile.Relief` / `HexTile.Biome` : `IsLand` = ni eau ni montagne (plus de test sur le nom des assets) ; `MovementCost` = coût du biome + 1 en colline.
- `Grid/HexGrid` : crée les `HexTile` en thread (`Task.Run`), voisins (`SetNeighbours`), instanciation par lots (coroutine), placement des joueurs par `DispatchPlayers` : candidates = terres loin du bord ; masse de terre suffisante (testée) : `StartPositionPicker.LandmassSizes` donne la taille de la masse de chaque case (terres reliées à pied : mer, lacs, fleuves et montagnes coupent), un départ exige au moins `startMinLandmass` cases (0 = automatique, `SuggestedMinLandmass` = un quart de la part de terre d'un joueur, ~20 sur 40×25 à 5 joueurs ; exclut les petites îles ; à revoir avec l'embarquement, un fleuve coupe un continent en deux masses) ; qualité des départs (testée) : case de départ plate ou en colline, prairie / plaine / forêt / jungle (`StartPositionPicker.IsGoodStart`), note = somme des `CellValue` dans un rayon de 2 (prairie, plaine 2 ; forêt, jungle, côte, lac, fleuve, colline 1 ; désert, toundra, taïga, marais, océan 0 ; montagne, neige −1) + `FreshWaterBonus` 4 si rivière d'arête, lac ou fleuve touche la case (`StartPositionPicker.Score`, `HexGrid.StartScore` / `HasFreshWater`) ; seul le tiers le mieux noté (`startBestFraction` 0,33) va au tirage, sinon (moins de bons départs que de joueurs) toutes les terres, avec un avertissement ; `LoadRiverEdges` charge les rivières pour `DispatchPlayers` comme pour `BuildRivers` (même événement, ordre non garanti) ; tirage délégué à `StartPositionPicker` (fonction pure testée : 1er au hasard, puis chacun au hasard parmi les cases de terre à au moins `minDistance` des joueurs déjà placés ; s'il n'y en a aucune, un des 10 % les plus éloignés), `TryGetTile(x, y, out tile)` (coordonnées offset, remplace l'ancien `GetTile`) et `TryGetTileAxial(axial, out tile)`. `CellsInRange(center, radius)` : cases existantes dans un rayon (`HexMetrics.AxialRange`, fonction pure testée).
- `Grid/HexTile` : plus de machine à états. Deux drapeaux indépendants : `IsDiscovered` (brouillard, `Discover()` révèle une seule fois) et `IsHovered` (survol, cases inexplorées comprises, affiché par le marqueur blanc `HexGrid.HoverMarker`, masqué sur la case sélectionnée ; posé sur `DisplayPosition` = `CentrePosition` à plat sous le brouillard, pour ne pas trahir le relief, utilisé aussi par l'aperçu du chemin). Troisième état `IsVisible` (vue en ce moment par le joueur affiché, posé par `SetVisibleNow` depuis `GameManager.OnVisibilityChanged`) : case découverte non vue = terrain mêlé de brume claire (`ApplyDim`, `Color.Lerp(_BaseColor, HexGrid.FogColor, HexGrid.FogAmount)` ; réglables dans l'Inspector de `Grid`, section « Brouillard », gris clair 0,85 et 0,5 par défaut, appliqués aussitôt en jeu via `OnValidate` → `RefreshDim` ; assombrir rendait les couleurs unies méconnaissables, proches de la mer ; `MaterialPropertyBlock`, matériaux intacts ; appelé aussi en fin de `Reveal`). Unités : visibles si case découverte et (case vue ou unité du joueur affiché, `HexTile.Viewer`, statique, posé dans `InitPlayers`) ; recalculé par `AddUnit`, `Discover`, `SetVisibleNow` (`Unit.SetVisible`, renderers masqués, objet actif) ; testé dans `HexTileTests`.
- `SelectionController` (Singleton créé par `GameManager`) : écoute les actions de `CameraController`. Clic gauche bref (sélection au relâchement ; un glissé déplace la carte, voir `CameraController`) : sélectionne une unité de la case survolée (découverte seulement), en priorité celle du joueur local (`HexTile.GetFirstUnit(owner)`, testé) ; case vide : désélection. Clic droit (`Interact`) : déplace l'unité sélectionnée par chemin (`PathFinder`), selon la connaissance du propriétaire (`Fog.IsExplored(owner, …)`, pas l'affichage) : case explorée = terre, sans unité d'un autre joueur si la case est vue en ce moment (`Fog.IsVisible(owner, …)`, paramètre `seenNow` ; hors vue, une unité ennemie est ignorée : le joueur ne la connaît pas), coût du terrain ; case inexplorée = supposée praticable, coût 1 (`HexTile.IsWalkableFor` / `MovementCostFor`, testés) ; on peut donc viser l'inconnu. Arrêt en route (avec la ligne de vue, une case du trajet peut être cachée derrière une forêt et se révéler eau ou occupée par un ennemi) : avant chaque case, `Unit.CanEnter(next)` (testé) vérifie qu'il reste un point et que la case, voisine donc vue, est vraiment praticable (`IsWalkableFor(owner, true, true)`) ; sinon l'unité s'arrête sur la case atteinte. Elle paie le vrai coût de chaque case parcourue (une case inconnue supposée à 1 peut coûter 2). Une case pleine traversée ne peut pas précéder un obstacle découvert : nos unités voient leurs voisines. Chemin coupé à ses points de mouvement, seulement pour une unité du joueur courant (celles des autres se sélectionnent mais ne bougent pas) ; `Unit.MoveAlong` change l'unité de case lui-même : case d'arrivée réservée dès le départ, reprise de la case atteinte si arrêt plus tôt. `Unit.Tile` tenu à jour par `HexTile.AddUnit`/`RemoveUnit` (testé) ; `SelectionController.SelectedTile` = `SelectedUnit.Tile` (calculé, suit l'unité). Commande ignorée pendant le trajet. Échap / Retour arrière : désélection. `HexGrid.Selector` suit l'unité à chaque image (`Update`). Aperçu du trajet au survol (`PathPreview`, enfant créé dans `Init`) : deux `LineRenderer` (shader `Sprites/Default`), clair pour la partie atteignable ce tour-ci, gris pour la suite ; case survolée interdite (eau, montagne) : chemin jusqu'à elle tout en rouge (troisième ligne, `ShowForbidden`), rien si même ce chemin n'existe pas ; masqué sans unité commandable (`CanCommand`) ; recalculé seulement si cible, origine ou points changent. `PathTo` partagé entre l'aperçu et `Command`. Sélection d'une autre unité : la vue glisse jusqu'à elle (`CameraController.CenterOn`, `centerDuration` 0,3 s, zoom inchangé, coupé par les flèches mais pas par le défilement par les bords ; reclic sur l'unité déjà sélectionnée : rien).
- `MouseController` : raycasts souris -> événements `OnMouseMoving`, `OnLeftMouseClick`, etc. Survol recalculé quand la souris bouge ou quand la caméra bouge (position / rotation comparées à l'image précédente).
- `CameraController` (Overhead / Focus) et `OrbitCameraWithTime`. Overhead : vue en perspective inclinée, nord en haut (`CinemachineFollow` en `WorldSpace`, `PositionDamping` à zéro sinon le `HardLookAt` fait pivoter la caméra au pan latéral ; décalage posé par `SetDistance` via `CameraMath.TiltedOffset`, fonction pure testée, `CameraMathTests`). L'inclinaison varie avec la distance : `pitchNear` 40° au plus près, `pitchFar` 85° au plus loin (réglé dans la scène, 70 par défaut dans le code : dézoom complet presque vu de dessus, pas 90 sinon le vecteur « haut » de la caméra est indéfini) (`CameraMath.Pitch`). Réglages : `fieldOfView` 30°, distance 40 à `MaxDistance` (défaut 120) ; `MaxDistance` = au moins `distanceMax` (250, plancher) et, si `fitMapOnMaxZoom`, la distance qui montre toute la carte (`CameraMath.FitDistance`, testée : champ horizontal selon le rapport de l'écran, profondeur × sin(pitchFar), marge 10 % ; carte entière seulement si la vue est centrée), `distanceZoomSpeed` (A/E, continu), `scrollZoomStep` (molette : 15 % de la distance par cran, molette vers le haut = éloigner, choix de l'utilisateur). Le zoom change la distance, plus le FOV. Clic gauche glissé (comme Civ 6) : la carte suit la souris, le point du sol saisi à l'appui reste sous le curseur (`DragMap`, `TryGroundPoint` sur le plan de la grille, `ClampTarget` ; arrête un glissement `CenterOn`) ; au-delà de `dragThreshold` (6 px) c'est un glissé, en deçà un clic : `OnFocusChanged` lit l'appui (`started`) et le relâchement (`canceled`) de `World/Select` (`PlayerInput` en Invoke Unity Events), la sélection part au relâchement d'un clic bref ; pas de défilement par les bords pendant l'appui. Clic du milieu (comme Civ 6) : la vue glisse jusqu'à la case survolée, découverte ou non (`CenterOnHovered` → `CenterOn(DisplayPosition)`, lu par `Mouse.current`). Pan (flèches, et souris à moins de `edgeScrollMargin` = 15 px d'un bord de la fenêtre, `edgeScroll`, seulement fenêtre active ; direction par `CameraMath.EdgeScrollDirection`, testée ; axes monde) à une vitesse proportionnelle au zoom (`PanSpeed` = `cameraSpeed` × distance / `distanceDefault`), borné : `ClampTarget` garde `CameraTarget` dans `HexGrid.WorldBounds` (rectangle des centres des cases, calculé par `HexMetrics.GridBounds`, fonction pure testée), réduit autour du centre en dézoomant (`recenterFrom` 0,6 : au-delà de 60 % du zoom max la zone autorisée rétrécit jusqu'au centre, `CameraMath.ShrinkRect` / `PanFreedom`, testées) ; appelé aussi par `SetDistance`, donc le dézoom complet recentre la vue et montre toute la carte.

## État du jeu
- Fait : génération de carte, brouillard (`IsDiscovered`), placement des joueurs, caméras, survol et sélection d'unité (marqueurs), déplacement par chemin animé, points de mouvement, tour par joueur (ordre fixe, joueur local d'abord, joueurs sans IA passés automatiquement), HUD (numéro de tour, joueur courant, unité sélectionnée et points restants), exploration (vision des unités), aperçu du chemin au survol.
- Ordre prévu : exploration (faite), traduction (faite, sauf le choix de langue dans un menu d'options), fleuves et lacs (faits), qualité des départs (faite), puis fondation des villes (gameplay villes et combats dans une autre session ; celle-ci reste pour la génération de carte et les bases du jeu, menus compris).
- Fleuves prévus (modèle Civ 7) : un calcul de débit à la génération (fonction pure testée : l'eau descend selon l'altitude, chaque case accumule le débit de son bassin versant ; seuils en proportions dans `MapRulesSettings`). Débit moyen = rivière sur les arêtes (entre deux cases voisines, ensemble d'arêtes dans `MapCell` / `HexTile`, `HasRiver(a, b)`) ; débit fort, vers l'embouchure = fleuve navigable sur les cases : `Relief.Water` + nouveau biome `River` (eau douce ; hérite d'`IsLand` faux, hauteur 0, pas de socle ; pas de relief `River`, qui obligerait à revoir les tests `Relief == Water`). Fréquence : chaque case de terre apporte son humidité au débit (beaucoup de rivières en zone humide, peu en désert, mais un grand fleuve peut traverser un désert par cumul, comme le Nil) ; seuils en percentiles des cases de terre (`RiverFraction` ~15 % de cases bordées par une rivière, `NavigableFraction` ~2–3 %), seuils absolus recalculés à chaque génération (fonction testée, comme `WithClimateThresholds`) ; garde-fous réglables : longueur minimale (~3 arêtes), cuvettes sans pente vers la mer (vers la voisine la plus basse, ou lac d'eau douce). Réglage à l'œil (`RandomSeed`, `RevealWholeMap`, Inspector de `MapGenerator`) : assez de rivières pour que l'eau douce compte dans le choix d'une ville, pas un fleuve à traverser à chaque tour. Gorges : naturelles (le fleuve suit les vallées, eau à hauteur 0 entre des collines). Étape 1a faite : `Grid/Hydrology` (classe pure testée, `HydrologyTests`, voisins fournis par l'appelant) : `Flow(altitude, relief, pluie, voisins)` → case aval de chaque terre et débit cumulé, par remplissage par priorité depuis l'eau (`SortedSet`, cuvettes remplies jusqu'au col, donc toujours une pente vers la mer s'il y a de l'eau ; sans eau : pas d'aval, `NoDownstream`) ; pluie = humidité ; `Navigable` → `bool[,]`, plus forts débits des cases de terre (`NavigableFraction` 10 % : les filtres suivants en retirent environ la moitié ; 3 % laissait souvent un seul fleuve ou aucun ; jamais en montagne ni sur la rangée de bord de la carte, exclue aussi du seuil : l'eau ne pouvant sortir de la carte, le bord collectait le débit de toute une région et longeait la carte en fleuve ; le débit croît vers l'aval, donc un fleuve navigable descend sans coupure jusqu'à la mer). `MapCell` reçoit `Flow`, `Downstream` (offset), `Navigable`. Étape 1c-1 faite : rivières sur les arêtes par un second calcul, de sommet en sommet (coin commun à trois cases ; le débit de case en case ne convient pas : une rivière posée entre deux cases successives du chemin de l'eau couperait la vallée en travers) : `Grid/RiverNetwork.Rivers` (pure, axial, testée `RiverNetworkTests`) : sommets dont les trois cases existent, altitude et pluie moyennes, « eau » si une de leurs cases est de l'eau (mer ou fleuve navigable : les rivières s'y jettent), même remplissage par priorité, débit cumulé ; `RiverFraction` 15 % des sommets de terre au plus fort débit → arête vers le sommet aval ; réseaux de moins de `RiverMinLength` (3) arêtes supprimés. Résultat `HashSet<RiverEdge>` (paire de cases voisines, ordre indifférent) dans `MapGenerator.RiverEdges`, calculé sur la carte finale ; compte dans la console (« N arêtes de rivière, M cases de fleuve navigable »). Plus de classement « rivière » par case. Étape 1b faite : `Biome.River` (ajouté en fin d'enum : la liste `BiomeTerrains` est enregistrée par numéro, ne jamais insérer au milieu) ; dans `BuildCells`, une case navigable devient `Relief.Water` + `Biome.River` (gorge si c'était une colline) ; assets `River.asset` (Id 12) + `river.prefab` / `River.mat` (copies de la côte ; couleur de repérage provisoire : magenta vif 1 / 0 / 1, pour distinguer les fleuves de la mer vus de loin ; à remplacer avec les modèles réalistes) ; entrée `River → River` dans `BiomeTerrains` de la scène. Infranchissable à pied, hauteur 0, pas de socle, sans autre code. Fleuves d'une case de large (fait, pour le rendu) : `Hydrology.SingleWidth` (testé), entre `Navigable` et `KeepLongRivers` : de l'aval vers l'amont (débit décroissant), une case est gardée si son aval est de l'eau ou gardé et si elle ne touche aucune case gardée hors de son aval et de l'aval de celui-ci (virage serré toléré) ; un affluent qui touche le fleuve sur deux cases est retiré avec son amont (redevient rivière d'arête). ## Pistes de conception (non décidées)
- Références : Civilization (5, 6, 7) et At the Gates (Jon Shafer). Direction encore ouverte entre les deux : At the Gates = une région (pas le monde entier), une seule époque (pas de changement d'âge), progression par les personnages : ils acquièrent des compétences qui débloquent unités, bâtiments et capacités (au lieu d'un arbre technologique) ; colle au thème des fiefs (seigneurs, vassaux). Conséquences possibles : carte régionale à bords fixes par défaut (`WrapWorld` reste une option), latitude réglable plutôt que pôles obligatoires. À trancher avec le gameplay (session villes et combats).
- Marqueurs observés dans Civ 6 (pour s'en inspirer, sans recopier) : unité sélectionnée = cercle plat blanc (deux cercles concentriques, une rose des vents / boussole dessinée au sol entre eux, petits rayons autour), et des rayons de lumière qui descendent du ciel sur elle ; survol d'une case = fenêtre d'informations près du curseur (terrain, coût en points de mouvement, attrait, continent, rendements) ; pendant le clic droit seulement (bouton maintenu ; l'ordre part au relâchement), le chemin vers la case visée est un trait en pointillés 3D (tirets clairs), et un cercle plat (avec de petits repères) marque la destination : doré si atteignable, rouge si infranchissable (sans trait), marron chocolat si la destination est hors du champ de vision, bleu marine (≈ 0,10 / 0,15 / 0,45) une fois relâché si l'unité n'a plus de points (trait et cercle restent affichés, mais l'unité ne suit pas le chemin d'elle-même au tour suivant) ; le trait est d'une seule couleur, avec une pastille numérotée (1, 2, 3…) sur la dernière case atteinte à chaque tour, la dernière sur la destination ; à la sélection, la zone atteignable ce tour-ci est entourée d'un contour cyan ; la fenêtre de survol détaille aussi bois, modificateur de défense, rendements. Commandes : clic gauche glissé = saisir la carte et la faire glisser (le point saisi reste sous le curseur), clic gauche bref = sélection ; d'où le déplacement au clic droit maintenu, relâché sur la destination.

## Règles de jeu décidées
- Une unité ne peut ni s'arrêter sur la case d'une unité d'un autre joueur, ni la traverser, sauf si un événement change la règle (alliance). Code : `IsWalkable` exclut `HexTile.HasUnitOfOtherPlayer(owner)` sur les cases vues en ce moment par le propriétaire (`IsWalkableFor(owner, explored, seenNow)`, testé) ; l'aperçu montre ces cases en rouge. Hors vue, l'unité ennemie est ignorée (pas de fuite d'information) ; un ennemi découvert en route arrête l'unité (`Unit.CanEnter`, voir `SelectionController`).
- Ordre vers la case d'une unité d'un autre joueur = attaque (à concevoir avec le combat : unité civile / militaire, dégâts, riposte). En attendant, refusé.
- Empilement (comme Civ 5 / 6) : au plus une unité civile et une militaire par joueur et par case (à ajuster plus tard). On peut traverser une case pleine de ses unités, pas s'y arrêter. Code : `HexTile.CanStop(unit)` (même propriétaire et même famille `IsMilitary`, l'unité elle-même ignorée, testé) ; case visée pleine = interdite (aperçu rouge, `PathTo` renvoie null) ; si les points s'épuisent sur une case pleine, l'unité s'arrête sur la dernière case libre (`PathFinder.LastStop`, testé, partagé par `Command` et l'aperçu via `StopCount`). Plus tard : échange de places entre deux unités amies voisines (Civ 6), formations.
- À décider : zones de contrôle (plus tard).

## Points fragiles connus

- `Player` n'est jamais déplacé sur sa case de départ (sa `transform` n'est pas utilisée) : seules les unités le sont. Optionnel : `player.transform.position = tile.CentrePosition` dans `InitPlayers`.
- `Player.StartingTile` / `StartingArea` : données calculées au lancement, `[NonSerialized]` (ni enregistrées ni visibles dans l'Inspector).
- Avertissement restant hors de notre code : « No script asset for BurstPlatformAotSettings » (package Burst).
- Intégrations d'éditeur : `com.unity.ide.visualstudio` (Visual Studio 2026, et VS Code via l'extension Unity) et `com.unity.ide.rider` ; `com.unity.ide.vscode`, déprécié, retiré.
- Nettoyage fait : packages `com.unity.visualscripting`, `com.unity.collab-proxy`, `com.unity.multiplayer.center` retirés ; assets `LeanTween`, `Ciconia Studio` (shaders Built-in), `DoubleSidedUnlitShader`, `Readme.asset` / `TutorialInfo` (modèle URP) et `ResourceManager` (script et objet de scène, liste jamais lue) supprimés. ## Révélation des zones de départ
- `GameManager.LocalPlayer` (champ `localPlayer`, par défaut le premier de `Players`) et `RevealAllPlayers` (coché par défaut, débogage). Décoché, seule la zone du joueur local est révélée et la caméra démarre sur sa case.
- `GameManager.RevealWholeMap` (débogage, décoché par défaut) : en fin d'`InitPlayers`, toutes les cases découvertes et visibles (`HexGrid.AllTiles`), et `OnVisibilityChanged` ignoré pour que tout reste visible. Affichage seulement (la connaissance `FogOfWar` n'est pas touchée) ; le déplacement suit la connaissance du propriétaire, pas cet affichage.
- Graine de carte : `MapGenerator.Seed` (les trois bruits en dépendent). `RandomSeed` (coché par défaut) : en jeu, nouvelle graine au hasard à chaque partie, affichée dans la console (« MapGenerator : graine N ») ; décocher et recopier la graine dans `Seed` pour rejouer une carte. Hors du mode Play, l'aperçu de l'Inspector garde `Seed`.
- Taille de carte : se règle uniquement sur `HexGrid` (Width / Height, 10 à 100) ; `MapGenerator` la lit au lancement de la génération (plus de Width / Height / UseHexGrid propres). Réglée à 40×25 dans la scène (20×20 était petit pour 5 joueurs : ~14 cases utiles chacun).
- Les unités posées sur des cases cachées sont masquées (voir `HexTile`).
- Exploration : les unités révèlent les cases autour d'elles en se déplaçant, dans la connaissance de leur propriétaire ; seul le joueur local est affiché ; on peut envoyer une unité dans l'inconnu (voir `SelectionController`).
- Ligne de vue (faite) : `LineOfSight.Visible` (classe pure testée, `LineOfSightTests`) trace la ligne hexagonale (`HexMetrics.AxialLine`, testée ; décalage ± pour les lignes le long d'une arête : vue si l'un des deux côtés est dégagé) vers chaque case du rayon. Hauteurs (`MapRules`, testé) : œil = `SightHeight` du relief (plat / eau 0, colline 2, montagne 4) ; obstacle = `ObstacleHeight` = relief + 1 pour forêt, taïga, jungle (`BlocksSight`). Une case intermédiaire cache la case visée si elle est plus haute que l'œil et au moins aussi haute que le sommet de la case visée : on voit ce qui dépasse (colline derrière une forêt, montagne derrière une forêt en colline), pas ce qui est de même hauteur (montagne derrière une montagne : cachée). Depuis une colline, on voit par-dessus forêts et collines, pas par-dessus une forêt en colline ni une montagne. Proche de Civ 5 / 6 (points sûrs : l'obstacle est vu, colline au-dessus des forêts, montagne bloque). Les cases voisines sont toujours vues. Branché dans `HexGrid.CellsInSight` (utilisé par `Unit.UpdateVision`) ; la zone de départ explorée reste un disque entier. Option possible : +1 de rayon en colline.
- Rendu du brouillard provisoire : les cases actuelles sont des couleurs unies minimalistes, à remplacer par des modèles plus réalistes. À revoir alors : désaturation par shader (Shader Graph, paramètre « brume » par case), voile ou nuages au-dessus des cases, ou passe de rendu plein écran ; la brume par `_BaseColor` continuera de teinter des matériaux texturés mais risque d'être trop simple.
- Brouillard par joueur, fait : connaissance par joueur (`FogOfWar`) et affichage pour le joueur local (cases explorées non vues sous une brume claire, unités des autres masquées hors vue). `RevealAllPlayers` (débogage) rend aussi les zones des autres visibles. `IsWalkable` suit la connaissance du propriétaire (fait) ; l'IA devra faire de même ; question ouverte : hot seat (affichage qui bascule par joueur, point de bascule : `HexTile.Viewer`) ou non.
