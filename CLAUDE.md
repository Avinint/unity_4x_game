# Fief (Fantasy Fiefdoms)

Jeu 4X heroic fantasy réaliste sous Unity. Langue de travail : français, réponses brèves et précises.

## Méthode de travail
- Avant toute écriture (code, scène), montrer les changements prévus (diff ou extraits avant/après, fichiers concernés) et attendre la validation explicite de l'utilisateur. Pas d'écriture avant le feu vert.
- CLAUDE.md et ajouts à `.gitignore` : écrire directement, sans montrer le diff ; résumer en une ligne ce qui a changé.
- Mettre CLAUDE.md à jour dans la même étape que le changement qu'il décrit (pas après coup), pour qu'il parte dans le même commit.
- Travailler par petites étapes, une à la fois, et vérifier en jeu entre deux étapes.
- Ne jamais commiter : l'utilisateur commite lui-même.

## Environnement
- Unity 6000.6.4f1, Windows. Rendu : URP (`Assets/Settings/URP-HighFidelity.asset`).
- Cinemachine 3 (`Unity.Cinemachine`) : `CinemachineCamera`, `CinemachineOrbitalFollow`, `Lens`.
- Input : Input System seulement (`PlayerControls.inputactions` pour les actions, `Mouse.current` dans `MouseController` et pour le défilement par les bords). Active Input Handling à régler sur « Input System Package (New) » (Project Settings → Player).
- MCP Unity (Editor ouvert sur le projet, package `com.unity.pipeline`), selon l'ordinateur :
  - `M:\Unity_Projects\Fantasy Fiefdoms` : `unity mcp configure claude-code --project-path "M:\Unity_Projects\Fantasy Fiefdoms"`.
  - `C:\Users\avini\UnityProject\unity_4x_game` : entrée locale `claude mcp add --scope local --transport stdio unity-editor-mcp -- unity mcp --project-path "C:\Users\avini\UnityProject\unity_4x_game"` (ne pas utiliser `unity mcp configure` ici : il écrase l'entrée utilisateur du projet FPS).
- Sortir du mode Play avant une recompilation ou un appel MCP : l'Editor ne répond plus pendant ce temps.
- Après une recompilation, relancer le mode Play : une partie lancée pendant le rechargement des scripts garde un état cassé (caméra non inclinée, HUD jamais mis en page).
- Touches simulées par MCP (`simulate_key`) : n'atteignent pas les actions du jeu (la vue Game n'a pas le focus) ; tester le clavier à la main.
- Tests EditMode (`Assets/Tests/EditMode`) : `unity test` refuse de tourner si l'Editor est ouvert sur le projet ; les lancer depuis le Test Runner ou par MCP (`eval` avec `TestRunnerApi`). Hors mode Play et scène enregistrée seulement : sinon le Test Runner échoue (mode Play) ou ouvre une fenêtre « sauvegarder la scène ? » qui bloque l'Editor.
- Ne pas éditer `.unity`/`.prefab` à la main si l'Editor est ouvert : passer par les outils MCP.

## Architecture (Assets/Scripts)
- `Singleton<T>` : base des managers (DontDestroyOnLoad seulement si l'objet est à la racine).
- `GameManager` : liste de `Player`, `InitPlayers` appelé sur `HexGrid.OnTileInstancesGenerated`, place les joueurs et unités de départ, événements `GameStart` / `TurnChange`. Tour par joueur : délégué à `TurnCycle<Player>` (classe pure testée, `TurnCycleTests` : ordre avec un premier joueur, `Advance()` renvoie true en début de manche, `Round`), créé en fin d'`InitPlayers` avec le joueur local en premier, puis `PlayerTurnStart(premier joueur)` levé pour ouvrir la partie ; `TurnOrder`, `CurrentPlayer`, `CurrentTurn` (= `Round`) en lecture. Entrée (`World/ChangeTurn` -> `ChangeTurn`, seulement si `CurrentPlayer == LocalPlayer`) termine le tour : `EndPlayerTurn` passe au suivant et lève `PlayerTurnStart(joueur)` ; après le dernier, nouvelle manche (`CurrentTurn++`, `TurnChange`). Les joueurs sans IA passent leur tour aussitôt (boucle jusqu'au retour du joueur local). `AddStartingUnits` passe chaque unité à `SetupStartingUnit` : ajout à `Player.units`, `Unit.Owner`, puis `Unit.UpdateVision(case)`. Brouillard par joueur : `GameManager.Fog` (`FogOfWar<Player>`) ; chaque joueur explore sa zone de départ (`Fog.Explore`) ; l'affichage suit le joueur local (`OnTileExplored` → `HexTile.Discover`) ; `RevealAllPlayers` n'affiche les zones des autres qu'en débogage.
- `FogOfWar<TPlayer>` : classe pure testée (`FogOfWarTests`). Par joueur, cases explorées (`HashSet`) et nombre d'unités qui voient chaque case (`Dictionary`, case vue si > 0). `Explore`, `AddWatcher`, `RemoveWatcher`, `IsExplored`, `IsVisible` ; événements `TileExplored` (une fois par case et par joueur) et `VisibilityChanged` (seulement aux transitions). Ne connaît pas la carte : l'appelant ne passe que des cases existantes (`HexGrid.CellsInRange`). Passage possible à des tableaux (index de case = ligne × Width + colonne) si une mesure le justifie.
- `UI/HUD` (UI Toolkit) : objet `HUD` de la scène (`UIDocument` + `HUD.cs`), fichiers dans `Assets/UI/HUD/` (`HUD.uxml`, `HUD.uss`, `HUDTheme.tss`, `HUDPanelSettings.asset`, 1920×1080 adapté à l'écran). Bande verticale transparente à droite (`rightBand`, 320 px), seuls deux cadres visibles, de même largeur (304 px), contenu centré, collés au bord de l'écran : en haut à droite (`turnPanel`, bordure sur les quatre côtés) une pastille à la couleur du joueur courant (`playerSwatch`, couleur posée par le code) puis « Tour N — Player 1 », mis à jour sur `TurnChange` et `PlayerTurnStart` ; en bas à droite (`unitPanel`, masqué sans sélection) l'unité sélectionnée et sa catégorie (« Warrior (mêlée) »), puis « Mouvement 1/2 », lus à chaque image dans `Update`. Tous les éléments en `picking-mode="Ignore"`.
- `Grid/MapGenerator` : trois bruits (altitude, humidité graine+1, chaleur graine+2) → `MapCell[,]` (`Relief`, `Biome`, `Terrain`), événement `OnTerrainMapGenerated(MapCell[,])`. Niveau de la mer = percentile `Rules.WaterFraction` ; collines / montagnes / basses terres = percentiles des seules terres ; latitude = y / (Height−1) (0 sud, 1 nord) ; côtes par `MapRules.CoastMask` avec les vrais voisins hexagonaux (`HexMetrics`). Terrain affiché : `MountainTerrain` pour une montagne, sinon `BiomeTerrains` (liste Biome → TerrainType, réglée dans la scène). Plus d'inversion des axes : la case (x, y) générée est la case offset (x, y) du jeu.
- `Grid/MapRules` (règles pures testées, `MapRulesTests`) : `Relief` (Water, Flat, Hill, Mountain), `Biome` (Ocean, Coast, Grassland, Plain, Desert, Forest, Taiga, Jungle, Tundra, Snow, Marsh), `MapRulesSettings` (proportions d'eau / collines / montagnes, poids de la latitude, refroidissement en altitude 0,2, climat en proportions des terres : `FrozenFraction` 8 % (neige), `TundraFraction` 12 % (toundra quelle que soit l'humidité), `ColdFraction` 15 % (taïga, toundra si sec), `HotFraction` 25 %, `DryFraction` 25 %, `WetFraction` 25 %, `MarshFraction` 8 % ; seuils absolus cachés, calculés à chaque génération par `WithClimateThresholds`, testé, qui ne modifie pas les réglages). `Percentile` (seuils d'altitude en proportions, indépendants de la graine), `ReliefAt`, `Temperature` (latitude : pôles froids, équateur chaud ; refroidit en altitude), `LandBiome` (tableau température × humidité type Whittaker : glacial → neige ; très froid → toundra ; froid → toundra si sec, sinon taïga ; tempéré → plaine / prairie / forêt ; chaud → désert / plaine / jungle ; marais sur terres plates basses très humides non froides), `WaterBiome` (côte si voisine d'une terre), `CoastMask`.
- Relief visible : `HexGrid` section « Relief » (`hillHeight` 1,5, `mountainHeight` 4, `ElevationOf` → `MapRules.Elevation`, testé). `HexTile.Elevation` calculée dans `CreateTerrain` ; `CentrePosition` inclut la hauteur (unités, marqueurs, aperçu, caméra suivent ; unités de départ posées sur `tile.CentrePosition`). Sous le brouillard le modèle inconnu reste à plat (ne trahit pas le relief) ; à la révélation, terrain en hauteur + socle (`AddPlinth` : prisme hexagonal sans couvercle `HexGrid.PlinthMesh` / `HexMetrics.BuildPlinthMesh`, testé, même matériau que le terrain, brume comprise). `AddGizmo` ne déplace plus le terrain.
- `HexTile.Relief` / `HexTile.Biome` : `IsLand` = ni eau ni montagne (plus de test sur le nom des assets) ; `MovementCost` = coût du biome + 1 en colline.
- `Grid/HexGrid` : crée les `HexTile` en thread (`Task.Run`), voisins (`SetNeighbours`), instanciation par lots (coroutine), placement des joueurs par `DispatchPlayers`, qui délègue le choix à `StartPositionPicker` (fonction pure testée : 1er au hasard, puis chacun au hasard parmi les cases de terre à au moins `minDistance` des joueurs déjà placés ; s'il n'y en a aucune, un des 10 % les plus éloignés), `TryGetTile(x, y, out tile)` (coordonnées offset, remplace l'ancien `GetTile`) et `TryGetTileAxial(axial, out tile)`. `CellsInRange(center, radius)` : cases existantes dans un rayon (`HexMetrics.AxialRange`, fonction pure testée).
- `Grid/HexTile` : plus de machine à états. Deux drapeaux indépendants : `IsDiscovered` (brouillard, `Discover()` révèle une seule fois) et `IsHovered` (survol, cases inexplorées comprises, affiché par le marqueur blanc `HexGrid.HoverMarker`, masqué sur la case sélectionnée ; posé sur `DisplayPosition` = `CentrePosition` à plat sous le brouillard, pour ne pas trahir le relief, utilisé aussi par l'aperçu du chemin). Troisième état `IsVisible` (vue en ce moment par le joueur affiché, posé par `SetVisibleNow` depuis `GameManager.OnVisibilityChanged`) : case découverte non vue = terrain mêlé de brume claire (`ApplyDim`, `Color.Lerp(_BaseColor, HexGrid.FogColor, HexGrid.FogAmount)` ; réglables dans l'Inspector de `Grid`, section « Brouillard », gris clair 0,85 et 0,5 par défaut, appliqués aussitôt en jeu via `OnValidate` → `RefreshDim` ; assombrir rendait les couleurs unies méconnaissables, proches de la mer ; `MaterialPropertyBlock`, matériaux intacts ; appelé aussi en fin de `Reveal`). Unités : visibles si case découverte et (case vue ou unité du joueur affiché, `HexTile.Viewer`, statique, posé dans `InitPlayers`) ; recalculé par `AddUnit`, `Discover`, `SetVisibleNow` (`Unit.SetVisible`, renderers masqués, objet actif) ; testé dans `HexTileTests`.
- `SelectionController` (Singleton créé par `GameManager`) : écoute les actions de `CameraController`. Clic gauche : sélectionne une unité de la case survolée (découverte seulement), en priorité celle du joueur local (`HexTile.GetFirstUnit(owner)`, testé) ; case vide : désélection. Clic droit (`Interact`) : déplace l'unité sélectionnée par chemin (`PathFinder`), selon la connaissance du propriétaire (`Fog.IsExplored(owner, …)`, pas l'affichage) : case explorée = terre sans unité d'un autre joueur, coût du terrain ; case inexplorée = supposée praticable, coût 1 (`HexTile.IsWalkableFor` / `MovementCostFor`, testés) ; on peut donc viser l'inconnu. Pas de recalcul en route : la partie parcourue en un tour est toujours connue (points de mouvement ≤ rayon de vision) et un ordre ne dure qu'un tour ; à ajouter avec les ordres sur plusieurs tours ou une unité qui va plus loin qu'elle ne voit (cavalerie). Chemin coupé à ses points de mouvement, seulement pour une unité du joueur courant (celles des autres se sélectionnent mais ne bougent pas) ; elle change de case (celle où elle s'arrête) dès le départ (`HexTile.RemoveUnit`/`AddUnit`) ; commande ignorée pendant le trajet. Échap / Retour arrière : désélection. `HexGrid.Selector` suit l'unité à chaque image (`Update`). Aperçu du trajet au survol (`PathPreview`, enfant créé dans `Init`) : deux `LineRenderer` (shader `Sprites/Default`), clair pour la partie atteignable ce tour-ci, gris pour la suite ; case survolée interdite (eau, montagne) : chemin jusqu'à elle tout en rouge (troisième ligne, `ShowForbidden`), rien si même ce chemin n'existe pas ; masqué sans unité commandable (`CanCommand`) ; recalculé seulement si cible, origine ou points changent. `PathTo` partagé entre l'aperçu et `Command`. Pas de recentrage de la caméra au clic.
- `MouseController` : raycasts souris -> événements `OnMouseMoving`, `OnLeftMouseClick`, etc. Survol recalculé quand la souris bouge ou quand la caméra bouge (position / rotation comparées à l'image précédente).
- `CameraController` (Overhead / Focus) et `OrbitCameraWithTime`. Overhead : vue en perspective inclinée, nord en haut (`CinemachineFollow` en `WorldSpace`, `PositionDamping` à zéro sinon le `HardLookAt` fait pivoter la caméra au pan latéral ; décalage posé par `SetDistance` via `CameraMath.TiltedOffset`, fonction pure testée, `CameraMathTests`). L'inclinaison varie avec la distance : `pitchNear` 40° au plus près, `pitchFar` 85° au plus loin (réglé dans la scène, 70 par défaut dans le code : dézoom complet presque vu de dessus, pas 90 sinon le vecteur « haut » de la caméra est indéfini) (`CameraMath.Pitch`). Réglages : `fieldOfView` 30°, distance 40 à `MaxDistance` (défaut 120) ; `MaxDistance` = au moins `distanceMax` (250, plancher) et, si `fitMapOnMaxZoom`, la distance qui montre toute la carte (`CameraMath.FitDistance`, testée : champ horizontal selon le rapport de l'écran, profondeur × sin(pitchFar), marge 10 % ; carte entière seulement si la vue est centrée), `distanceZoomSpeed` (A/E, continu), `scrollZoomStep` (molette : 15 % de la distance par cran, molette vers le haut = éloigner, choix de l'utilisateur). Le zoom change la distance, plus le FOV. Pan (flèches, et souris à moins de `edgeScrollMargin` = 15 px d'un bord de la fenêtre, `edgeScroll`, seulement fenêtre active ; direction par `CameraMath.EdgeScrollDirection`, testée ; axes monde) à une vitesse proportionnelle au zoom (`PanSpeed` = `cameraSpeed` × distance / `distanceDefault`), borné : `ClampTarget` garde `CameraTarget` dans `HexGrid.WorldBounds` (rectangle des centres des cases, calculé par `HexMetrics.GridBounds`, fonction pure testée), réduit autour du centre en dézoomant (`recenterFrom` 0,6 : au-delà de 60 % du zoom max la zone autorisée rétrécit jusqu'au centre, `CameraMath.ShrinkRect` / `PanFreedom`, testées) ; appelé aussi par `SetDistance`, donc le dézoom complet recentre la vue et montre toute la carte.
- `Player.Color` (réglée dans la scène : cramoisi, violet, blanc, noir, cyan) et `Player.PlayerColorMaterial` (URP Lit uni, un par joueur, pour socles, bannières, frontières…). Héraldique : blason du joueur prévu sous le nom `CoatOfArms`, objet affiché sur les unités `Banner` (plus tard).
- `UnitCategory` (enum : Civilian, Melee, Ranged, Cavalry, Siege, Recon ; liste modifiable) + `DisplayName()` (méthode d'extension, nom français affiché) ; `UnitType.Category` (Settler `Civilian`, Warrior `Melee`) et `UnitType.IsMilitary`. Testé (`UnitCategoryTests`). Servira pour l'empilement, le droit d'attaquer et les bonus de combat.
- Textes affichés en français écrits en dur, regroupés (ex. `DisplayName()`, `HUD.cs`). Traduction prévue avec le package Localization de Unity, en étape à part (avant les villes).
- `Unit` + `Unit/State/*` : renseigner `Owner` crée un socle de couleur (`OwnerBase`, cylindre aplati sans collider, `ownerBaseDiameter` 4,5) en attendant la bannière ; il suit `SetVisible` (testé, `UnitTests`). États d'unité (Idle / Selected utilisés, les autres vides). `MoveAlong(path)` (liste de `HexTile`) : déplacement animé case par case (`moveSpeed`, drapeau `IsMoving`, sans passer par `MovingUnitState`), coûte 1 point par case ; à chaque case atteinte, `UpdateVision` met à jour la connaissance de son propriétaire (retire les cases vues depuis l'ancienne position, `seenCells`, ajoute celles dans `UnitType.SightRadius`, 2 par défaut). À faire avec le combat : retirer la vision d'une unité détruite. `MovementPoints` vient de `UnitType.MovementPoints` (2 par défaut), rechargé par `ResetMovementPoints` au démarrage et au début du tour de son propriétaire (`Owner`, événement `PlayerTurnStart`, abonnement dans `OnEnable`/`OnDisable`).
- Coût de déplacement : `TerrainType.MovementCost` (1 ; Forest, Jungle, Snow à 2), lu par `HexTile.MovementCost`. On peut entrer dans une case tant qu'il reste au moins un point (règle Civ 5) : `PathFinder.ReachableCount(coûts, points)` (testé) coupe le chemin dans `Command` et sépare clair/gris dans l'aperçu ; `MoveAlong` retire la somme des coûts (plancher 0).
- `Grid/PathFinder` : A* pur sur coordonnées axiales, `FindPath(origin, destination, isPassable[, stepCost])`, coût 1 par case par défaut, chemin le moins coûteux sinon ; renvoie le chemin sans la case de départ, liste vide si même case, null si inaccessible. Testé (`PathFinderTests`).

## État du jeu
- Fait : génération de carte, brouillard (`IsDiscovered`), placement des joueurs, caméras, survol et sélection d'unité (marqueurs), déplacement par chemin animé, points de mouvement, tour par joueur (ordre fixe, joueur local d'abord, joueurs sans IA passés automatiquement), HUD (numéro de tour, joueur courant, unité sélectionnée et points restants), exploration (vision des unités), aperçu du chemin au survol.
- Ordre prévu : exploration avant la fondation des villes.
- Pas branché : IA des autres joueurs, fin de partie (`MaxTurns` inutilisé), ressources.
- Refonte de la génération : faite (relief et biome séparés, voir `MapGenerator` / `MapRules` ; continents ~65 % d'eau, pôles froids, toundra puis taïga, marais, collines et montagnes surélevées). Assets ajoutés : `Snow.asset` (ex-`TerrainType.asset`) + `snow.prefab` / `Snow.mat`, `Taiga.asset` + `taiga.prefab` / `Taiga.mat`, `Marsh.asset`. Distance minimale entre joueurs : `HexGrid.PlayerSpawningMinDistance` = 0 (automatique) → `StartPositionPicker.SuggestedMinDistance(terres disponibles, joueurs, rayon de départ)` ≈ 2 √(terres / (3 × joueurs)), avec un plancher de 2 × rayon de départ + 2 pour que les zones de départ ne se touchent pas (sans plancher, 5 joueurs sur 20×20 donnaient 4 et des unités voisines), testé ; une valeur positive force l'espacement (réglage de partie : départs serrés ou espacés). Vraie règle de placement (`StartPositionPicker.Pick(…, minDistance)`) ; le message « distance minimale non respectée » ne sort plus qu'au repli.
## Règles de jeu décidées
- Une unité ne peut ni s'arrêter sur la case d'une unité d'un autre joueur, ni la traverser, sauf si un événement change la règle (alliance). Code : `IsWalkable` exclut `HexTile.HasUnitOfOtherPlayer(owner)` (testé) ; l'aperçu montre ces cases en rouge. Petite fuite connue : testé sur toute case explorée, même pas vue en ce moment (à limiter aux cases vues).
- Ordre vers la case d'une unité d'un autre joueur = attaque (à concevoir avec le combat : unité civile / militaire, dégâts, riposte). En attendant, refusé.
- À décider : limite d'empilement (piste : une unité civile et une unité militaire max par case) ; zones de contrôle (plus tard).

## Points fragiles connus
- `BaseUnitState` : classe simple (plus de `Singleton`/`MonoBehaviour`), états créés avec `new`. `Unit` a un `State` et un `ChangeState` (Idle / Selected utilisés, les autres états sont vides).
- `Player` n'est jamais déplacé sur sa case de départ (sa `transform` n'est pas utilisée) : seules les unités le sont. Optionnel : `player.transform.position = tile.CentrePosition` dans `InitPlayers`.
- `Player.StartingTile` / `StartingArea` : données calculées au lancement, `[NonSerialized]` (ni enregistrées ni visibles dans l'Inspector).
- Avertissement restant hors de notre code : « No script asset for BurstPlatformAotSettings » (package Burst).
- Intégrations d'éditeur : `com.unity.ide.visualstudio` (Visual Studio 2026, et VS Code via l'extension Unity) et `com.unity.ide.rider` ; `com.unity.ide.vscode`, déprécié, retiré.
- Nettoyage fait : packages `com.unity.visualscripting`, `com.unity.collab-proxy`, `com.unity.multiplayer.center` retirés ; assets `LeanTween`, `Ciconia Studio` (shaders Built-in), `DoubleSidedUnlitShader`, `Readme.asset` / `TutorialInfo` (modèle URP) et `ResourceManager` (script et objet de scène, liste jamais lue) supprimés. Les ressources du jeu seront conçues avec les villes.
- Case visée à la souris : les cases révélées ont des `MeshCollider` taggés « Grid » (dessus et socle, `HexTile.AddColliders` en fin de `Reveal`) ; `MouseController` garde le collider « Grid » le plus proche, donc le sommet d'une case surélevée est touché avant le sol ; `HexGrid.OnMouseMove` calcule la case depuis le point touché dans le repère de la grille (`transform.position` de `HexGrid`, plus celui de l'objet touché). Sous le brouillard, c'est le maillage plat de `Grid` (y = 0) qui est touché.

## Révélation des zones de départ
- `GameManager.LocalPlayer` (champ `localPlayer`, par défaut le premier de `Players`) et `RevealAllPlayers` (coché par défaut, débogage). Décoché, seule la zone du joueur local est révélée et la caméra démarre sur sa case.
- `GameManager.RevealWholeMap` (débogage, décoché par défaut) : en fin d'`InitPlayers`, toutes les cases découvertes et visibles (`HexGrid.AllTiles`), et `OnVisibilityChanged` ignoré pour que tout reste visible. Affichage seulement (la connaissance `FogOfWar` n'est pas touchée) ; le déplacement suit la connaissance du propriétaire, pas cet affichage.
- Graine de carte : `MapGenerator.Seed` (les trois bruits en dépendent). `RandomSeed` (coché par défaut) : en jeu, nouvelle graine au hasard à chaque partie, affichée dans la console (« MapGenerator : graine N ») ; décocher et recopier la graine dans `Seed` pour rejouer une carte. Hors du mode Play, l'aperçu de l'Inspector garde `Seed`.
- Taille de carte : se règle uniquement sur `HexGrid` (Width / Height, 10 à 100) ; `MapGenerator` la lit au lancement de la génération (plus de Width / Height / UseHexGrid propres). 20×20 est petit pour 5 joueurs (~14 cases utiles chacun) ; essayer ~40×25.
- Les unités posées sur des cases cachées sont masquées (voir `HexTile`).
- Exploration : les unités révèlent les cases autour d'elles en se déplaçant, dans la connaissance de leur propriétaire ; seul le joueur local est affiché ; on peut envoyer une unité dans l'inconnu (voir `SelectionController`).
- Plus tard : relief et visibilité (ligne de vue). Idée : `TerrainType` reçoit une altitude et un « bloque la vue » (montagne, forêt) ; une unité en hauteur voit plus loin ; fonction pure testée qui trace la ligne hexagonale entre deux cases et s'arrête au premier obstacle plus haut que l'observateur. Remplacera `AxialRange` dans `HexGrid.CellsInRange`.
- Rendu du brouillard provisoire : les cases actuelles sont des couleurs unies minimalistes, à remplacer par des modèles plus réalistes. À revoir alors : désaturation par shader (Shader Graph, paramètre « brume » par case), voile ou nuages au-dessus des cases, ou passe de rendu plein écran ; la brume par `_BaseColor` continuera de teinter des matériaux texturés mais risque d'être trop simple.
- Brouillard par joueur, fait : connaissance par joueur (`FogOfWar`) et affichage pour le joueur local (cases explorées non vues sous une brume claire, unités des autres masquées hors vue). `RevealAllPlayers` (débogage) rend aussi les zones des autres visibles. `IsWalkable` suit la connaissance du propriétaire (fait) ; l'IA devra faire de même ; question ouverte : hot seat (affichage qui bascule par joueur, point de bascule : `HexTile.Viewer`) ou non.
